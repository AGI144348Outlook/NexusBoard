# Operator docking and durable shift continuity

The **System Entity remains permanent** while a ChatGPT conversation or preauthorized cloud scheduler temporarily directs permitted work.

## Proposed lifecycle

1. Open compatible MCP host and request a docking UI or ordinary tool output.
2. Authenticate human and obtain explicit consent to purpose and scope.
3. Issue NexusBoard-controlled session/lease with expiry, not a presumed permanent host conversation ID.
4. Read authorized mission and evidence status.
5. Perform scoped requests with server-side policy checks and conflict control.
6. Checkpoint pending jobs, approvals, budget and evidence; revoke/release lease.

When a cloud operator resumes standing tasks, it may execute only preapproved work. At concurrent shifts, mission ownership/locks prevent duplicate external actions. Revocation blocks new privileged requests; already-running work needs separate policy. Future operators receive an evidence-backed handoff rather than relying on the previous conversation's narrative.
