# Two networks: evidence and evidence-about-evidence

**Network of Evidence**: first-order entities (source, observation, claim, hypothesis, result) with typed relations (supports, contradicts, cites, depends-on, revises).

**Evidence of the Network**: second-order records explaining who proposed a relation, which exact edge and revision was evaluated, source independence, authorizing role, method, dissent, and temporal outcome.

## Integrity rules

- **Storing an edge** does not validate it.
- An internal explanation of provenance does not independently verify its own assertion.
- Two outlets reprinting one original measurement are not independent corroboration.
- Never overwrite the source observation because a later interpretation changes.
- Propagate source changes only across proven/declared typed dependencies and flag impacted conclusions **for review**.
- SQL roles, constitutional seats and contextual evidentiary roles are distinct.

## Proposed flow

Capture → normalize → classify → resolve → propose relation → assess independently → govern acceptance/defer/rejection → append revision → time-aware retrieval.

Retain lawful historical attribution while meeting privacy or legal deletion requirements. Model similarity suggests candidate links only; it does not prove their support.
